# Evergreen Farm website

The public website for Evergreen Farm, a farm wedding and event venue: a static Astro site hosted
on GitHub Pages. It is the website half of WP01 in
[evergreenAI](https://github.com/hongzengAI/evergreenAI) (private). The pipeline there owns the
business facts, the inquiry intake and the calendar; this repo only renders them.

**Status: preview.** Every page carries `noindex`, a preview banner and highlighted placeholders
for anything the owner hasn't confirmed. A production build refuses to finish until each
placeholder is resolved (see [Launch checklist](#launch-checklist)).

## How it fits together

```text
evergreenAI (private)                          this repo (public)                 visitors
businesses/evergreen/*.yaml ──export──▶ src/data/business.json ─┐
Google Calendar ──availability_view──▶ src/data/availability.json ├─ build ─▶ GitHub Pages ─▶ browser
                                       src/assets/photos/*.jpg ──┘   (Actions)
intake endpoint (pipeline host) ◀──────────── inquiry form POST ──────────────────── browser
```

- **Facts come from the SSOT.** `src/data/business.json` is generated by
  `ruby scripts/export_site_data.rb . ../evergreen-farm-site/src/data/business.json` in evergreenAI.
  Never edit it by hand: change `facts.yaml`, `offers.yaml` or `spec.yaml` there, then re-export.
  It holds only customer-facing data (no targets or internal notes), because this repo is public.
- **Copy is gated on facts.** Pages wrap claims in `<Fact id="…">`. A confirmed fact renders
  normally. An unconfirmed one renders highlighted, and a fact that hasn't been collected yet
  renders a "To confirm · 待确认" block with the owner's question in Chinese. Each of these carries
  `data-pending`, which `scripts/check-site.mjs` counts after every build.
- **Availability** is a list of booked days. The pipeline's `availability_view` module rewrites
  `src/data/availability.json` from Google Calendar and commits it only when it changes, and the
  commit triggers a deploy. A nightly scheduled build rolls the 18-month window forward. Contract:
  `schemas/availability.schema.json` in evergreenAI.
- **The inquiry form** posts to the pipeline's intake endpoint (`PUBLIC_INQUIRY_ENDPOINT`).
  - Without JavaScript it is a plain POST, and the endpoint answers `303` to `/inquire/thanks/`.
  - With JavaScript it sends the same urlencoded body with `fetch`. That is a CORS simple request
    (no preflight), so the endpoint must return `Access-Control-Allow-Origin` for the site's origin
    and should check `Origin` itself.
  - Spam defence is a honeypot (`company_website`) plus a time trap (`started_at`). Both are checked
    on the server, and Turnstile can be added if spam appears.
  - Contract: `schemas/inquiry.schema.json` in evergreenAI.
  - Until the endpoint exists, submitting shows what would have been sent and sends nothing.
- **Attribution.** The first page of a visit stores its `utm_*` tags and external referrer in
  `sessionStorage`. The form sends them with the inquiry, so the pipeline can count inquiries by
  channel.

## Develop

Node 22.22 or newer (CI uses Node 24 from `.nvmrc`).

```sh
npm ci
npm run dev        # http://localhost:4321
npm run build      # astro build + scripts/check-site.mjs
```

`npm run build` prints the list of items still to confirm. Try a production build locally with
`PUBLIC_PREVIEW=false npm run build`; it fails until that list is empty.

| Variable (GitHub repo variable) | Purpose | Default |
|---|---|---|
| `PUBLIC_PREVIEW` | `false` removes the banner and `noindex`, adds the sitemap, enforces the launch checks | `true` |
| `PUBLIC_INQUIRY_ENDPOINT` | Intake URL on the pipeline host | empty: preview submit |
| `PUBLIC_TOUR_URL` | Google Calendar booking page for tours | empty: "Book a tour" opens the form |
| `PUBLIC_GA4_ID` | GA4 measurement ID; loaded only when not in preview | empty |

`SITE_URL` and `BASE_PATH` are filled in by `actions/configure-pages`, so the same workflow serves
`https://hongzengai.github.io/evergreen-farm-site/` now and the custom domain later.

## Hosting on GitHub Pages

- **The repo is public** because GitHub Free only publishes Pages from public repos. Nothing
  private belongs here; the export script only writes customer-facing fields.
- **Deploys** run on every push to `main`, nightly, and on demand
  (`.github/workflows/deploy.yml`). Settings → Pages → Source must be **GitHub Actions**.
- **Limits:** a 1 GB site, a soft 100 GB/month of bandwidth, and 10-minute deploys. That is far
  more than a venue site needs.
- **Policy:** GitHub's terms rule out using Pages "to run your online business, e-commerce site"
  or for sites "primarily directed at facilitating commercial transactions". A brochure site with
  an inquiry form and no payments is a common, low-risk use, but it is GitHub's call. If that
  ever becomes a problem, `dist/` deploys unchanged to Cloudflare Pages or Netlify.
- **Response headers:** Pages can't send custom headers, so `noindex` goes in each page's
  `<meta>`. `robots.txt` never disallows, because crawlers have to fetch a page to see its noindex.
- **Inactivity:** GitHub disables scheduled workflows in public repos after 60 days without
  activity. Availability commits from the pipeline count as activity. If the nightly build stops,
  re-enable it in the Actions tab.

### Custom domain cutover (EvergreenFarmVenue.com)

The domain in the spec was **not registered** as of 2026-10-18. Register it first, in the
business's own registrar account.

1. Verify the domain for the account (profile Settings → Pages → Add a domain, then the
   `_github-pages-challenge-hongzengAI` TXT record) **before** pointing DNS at GitHub. This
   prevents takeover.
2. At the DNS host, add:
   - A `@` → 185.199.108.153, 185.199.109.153, 185.199.110.153, 185.199.111.153
   - AAAA `@` → 2606:50c0:8000::153, 2606:50c0:8001::153, 2606:50c0:8002::153, 2606:50c0:8003::153
   - CNAME `www` → `hongzengai.github.io`

   No wildcard records. Keep the TXT record.
3. Repo Settings → Pages → Custom domain: `evergreenfarmvenue.com`. With an Actions deploy no
   `CNAME` file is needed.
4. Wait for the certificate (up to 24 hours), then tick **Enforce HTTPS**.
5. Re-run the deploy so `SITE_URL` and `BASE_PATH` pick up the domain.

Google Workspace mail for the domain (O04 in evergreenAI) needs its own MX, SPF, DKIM and DMARC
records on the same zone. They don't conflict with the records above.
